# 容器服务巡检内容重构

**日期**：2026-04-27
**版本**：v2.0 → v2.1

---

## 一、背景

原容器巡检区块（区块四）仅通过 `container_query` 统计每台机器的运行中容器数量，信息维度过于单薄，无法满足运维对容器服务健康状况的巡检需求。

本次重构引入两个新查询维度：
- **容器服务详情**：名称、镜像、运行状态、启动时间
- **容器端口状态**：关联 `net_response_result_code` 指标，展示各服务端口的连通性

---

## 二、数据模型变更

### 新增结构体

```go
// ContainerPort 容器端口连通状态
type ContainerPort struct {
    Target string `json:"target"` // 如 172.31.36.36:10000
    OK     bool   `json:"ok"`     // true 表示连通
}

// ContainerService 单个容器服务信息
type ContainerService struct {
    Name      string          `json:"name"`
    Image     string          `json:"image"`
    Status    string          `json:"status"`     // running / exited / paused 等
    StartedAt int64           `json:"started_at,omitempty"`
    Ports     []ContainerPort `json:"ports,omitempty"`
}
```

### 扩展现有结构体

```go
// ContainerSummary 单台机器容器运行情况（区块四）
type ContainerSummary struct {
    Instance     string             `json:"instance"`
    RunningCount int                `json:"running_count"`
    Services     []ContainerService `json:"services,omitempty"` // 新增
}
```

**涉及文件**：`internal/model/model.go`

## 三、模板配置扩展

### 新增 YAML 字段

在保留原有 `container_query` 的基础上，新增两个可选查询字段：

```yaml
# 容器运行情况
container_query: "count by(ident) (docker_container_status_started_at{container_status='running',group='{{.group}}'})"
container_services_query: "docker_container_status_started_at{group='{{.group}}'}"       # 新增
container_ports_query: "net_response_result_code{group='{{.group}}'}"                    # 新增
```

| 字段 | 用途 | 必填 |
|------|------|------|
| `container_query` | 统计每台机器运行中容器数量 | 否 |
| `container_services_query` | 获取容器服务详情（名称、镜像、状态、启动时间） | 否 |
| `container_ports_query` | 获取端口连通状态（关联 net_response） | 否 |

三查询独立执行、独立降级：任意查询缺失或失败不影响其他查询正常工作。

**涉及文件**：`internal/service/inspector.go`

## 四、查询逻辑重构

### 执行流程（区块四）

```
1. 统计查询（container_query）
   → summaryMap[ident] = running_count

2. 服务详情查询（container_services_query）
   → serviceMap[ident][container_name] = ContainerService
   标签提取优先级：container_name > name > container

3. 端口状态查询（container_ports_query）
   → portMap[ident][service] = []ContainerPort
   OK = (value == 0)  // net_response_result_code 0 为成功

4. 关联端口到服务
   → 按 ident + service(container_name) 匹配

5. 组装结果
   → 遍历所有 ident，生成 ContainerSummary 列表
   → 若未配置 container_query，自动从服务状态统计 running 数量
```

### 新增方法

| 方法 | 文件 | 说明 |
|------|------|------|
| `queryContainerServices()` | `internal/service/inspector.go` | 执行容器服务详情查询 |
| `queryContainerPorts()` | `internal/service/inspector.go` | 执行端口状态查询 |

## 八、向后兼容性

| 场景 | 行为 |
|------|------|
| 旧模板仅有 `container_query` | 正常运行，输出旧格式统计表格 |

## 九、时间戳修复（当天巡检）

### 问题
`QueryInstant` 使用 `report_date` 当天的 `23:59:59` 作为查询时间戳。当用户选择**今天**执行巡检时，`etime` 大于当前时间，VM `query` API 在查询未来时间点时返回空结果，导致所有中间件和容器数据丢失。

### 修复
新增 `instantTs` 变量：若 `report_date` 是当天（或未来），则使用当前 Unix 时间戳替代 `etime`。

```go
instantTs := etime
if now := time.Now().Unix(); now < etime {
    instantTs = now
    log.Printf("[Inspector] report_date=%s is today or future, using instantTs=%d", reportDate, instantTs)
}
```

所有 `QueryInstant` 查询统一使用 `instantTs`（中间件状态、容器统计、服务详情、端口状态）。`QueryRange`（磁盘使用率）仍使用全天时间范围，不受影响。

**涉及文件**：`internal/service/inspector.go`

## 十、调试排查经验

| 问题现象 | 根因 | 验证方法 |
|----------|------|----------|
| 所有中间件/容器查询返回空 | VM 中 `group` 标签值与项目变量不匹配 | 直接用 `curl` 调用 VM `/api/v1/query` 接口验证 |
| 容器服务详情为空但统计有值 | `docker_container_status_started_at` 的 labels 中无 `container_name`/`name`/`container` | 查看 VM 返回的完整 labels |
| 端口状态未关联到容器 | `net_response_result_code` 的 `service` 标签值与 `container_name` 不完全匹配 | 对比两个查询返回的 `service` 和 `container_name` |
